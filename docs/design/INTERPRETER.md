# Interpreter：执行与模块后端

本文件汇合 [Effect](EFFECT.md)、[Handler 与 impl](IMPL.md)、[AST](AST.md)、[Hanging](HANGING.md) 和[资源规则](RESOURCE.md)，定义统一运行职责。

## 1. 启动入口

```haskell
main = interpreter ast effect
```

ast 提供模块控制结构，effect 是注册集合，Hanging 随程序描述装配。每份注册通过存在封装保存具体 effect、handler 类方法字典以及 bind 指定的 impl。

Free 承载操作组合，AST 承载模块控制；解释器把它们转换为可调度计划，由运行时执行。

## 2. 一次调用与依赖注入

1. 根据 AST 或事件定位目标，确定注册身份、模块位置和执行身份。
2. 解析 input、参数来源以及 scope/错误关联，按分类驱动所需上游。
3. 通过 Read/Map 准备 require 参数，等待所需能力；失败进入错误路径。
4. 打开目标 effect 的存在封装，取得具体表示、handler 能力字典和 bind 绑定的 impl。
5. 建立本次调用环境，运行 impl，将 input 指定的上游 effect 作为业务输入。
6. impl 调用类方法句柄；该方法使用相应 instance 的解释，以及本次调用的参数和资源能力。
7. 完成原子操作，取得本次目标 effect，分别记录状态、业务结果和资源变化。
8. 唤醒依赖者，继续控制流；scope 退出时调度 Close 的 impl，通过关闭句柄释放资源。

步骤 4—6 承接依赖注入：具体 effect 的字典提供句柄解释，调用环境提供执行数据和能力入口。注册描述用于调度，impl 的返回值用于记录本次执行结果。资源清理和错误处理使用各自的启动条件。

## 3. 状态、共享与重复执行

运行时保存 waiting、running、succeeded、failed、cancelled；对外可投影为较简的 pending/succ/failed。业务结果单独保存，Read 按执行身份读取。

同次执行的并发消费者通过原子的“检查并启动”共享操作。新监听轮次、重试或 stress 请求建立相应的新执行身份。

后端分别诊断当前轮次的依赖等待和死锁，并管理显式 loop 的跨轮次触发。

## 4. VM 式模块后端

后端按 AST 模块路径、注册身份、执行身份和 scope 身份定位操作，提供三个视图：

| 视图 | 内容 |
|---|---|
| 静态 IR | 注册、操作组合、值来源、资源关联、handler 实例解释与 impl 绑定 |
| 运行快照 | 状态、等待原因、结果摘要、资源状态、本次采用的句柄解释和 impl |
| 事件流 | 开始、等待、完成、失败、取消、获取和释放，以及时间与触发来源 |

同一组视图支持外部工具：

| 功能 | 后端行为 |
|---|---|
| listen | 按模块或执行订阅事件与快照 |
| mock | 为场景选择已编译的句柄解释与 impl，记录实际采用的组合 |
| stress | 按输入、重复次数和并发度调度独立调用 |
| log/show | 展示模块结构、连接、状态、耗时、等待、资源以及解释与绑定 |

观察读取既有事件和快照。mock 保留原始声明，场景选择在本次调用启动时确定；资源获取与释放采用配套解释。stress 遵守去重、取消和清理协议。外部触发与 Hanging 一样进入统一调度。

IR 提供模块操作边界的可观测性；宿主函数通过框架接口和主动上报提供进一步的内部事件。

## 5. JSON 与插件启动

序列化保存：

- Effect IR、AST、Hanging 描述及稳定引用。
- 参数契约、准备表达式、配置与版本信息。
- handler 实例解释的插件标识，以及 bind 所指定 impl 的标识。

源码 record 以 handler 声明句柄、以 bind 绑定函数。导出配置时，用稳定标识表示两者。加载器从已编译插件恢复具体 effect 表示、类型类字典和 impl，建立对应的存在包；函数闭包、活资源和线程保留在运行时。

```text
读取配置 → 解码契约与参数 → 解析引用和插件
         → 恢复 handler 实例与 impl 绑定 → 建立调用环境 → 启动
```

加载器完成引用与参数解析，报告缺失实现或解码错误。类型类实例由插件编译提供，运行时选择并装配已编译的封装。

## 6. 完成标准

同一份注册应贯通“阅读声明”“通过句柄注入依赖并执行操作”“按模块观察”“场景选择解释与实现”“重复负载测试”，保持身份、值与资源规则一致。具体实现顺序和验证场景见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。
