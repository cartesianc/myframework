# Interpreter：执行与模块后端

本文件汇合 [Effect](EFFECT.md)、[Impl](IMPL.md)、[AST](AST.md)、[Hanging](HANGING.md) 和[资源规则](RESOURCE.md)，规定它们怎样共同运行。此处定义职责，不实现解释器。

## 1. 启动入口

```haskell
main = interpreter ast effect
```

ast 提供模块控制结构；effect 是包含显式 impl 绑定的注册集合；Hanging 随程序描述装配。解释器把描述转换成运行计划，由运行时驱动宿主操作。

Free 承载操作组合，AST 承载模块控制。两种结构都应解释为可调度计划，不在普通遍历时立即运行全部 IO。

## 2. 一次调用

1. 根据 AST 或事件定位目标，确定注册身份、模块位置和执行身份。
2. 解析 input、参数来源以及 scope/错误关联，按分类驱动所需上游。
3. 通过 Read/Map 准备 require 参数，等待所需能力；失败则进入错误路径。
4. 选择本次有效实现，构造 Binding，调用 record 已绑定的 impl。
5. impl 接收 input，返回当前目标的待执行表示。
6. 后端运行宿主动作，分别记录状态、结果和资源变化。
7. 唤醒依赖者，继续控制流；退出 scope 时执行清理协议。

计划必须区分静态注册与本次动作，防止把 impl 的输出重新当成待绑定注册而无限调用 handler。资源清理和错误处理使用各自的启动条件。

## 3. 状态、共享与重复执行

运行时保存 waiting、running、succeeded、failed、cancelled；对外可投影为较简的 pending/succ/failed。业务结果单独保存，Read 按执行身份读取。

同次执行的并发消费者通过原子的“检查并启动”共享操作。仅查看静态成功标志不足以防止并发重复启动。

新监听轮次、重试或 stress 请求使用相应的新执行身份。去重不能永久禁止同一个注册再次执行。当前轮次的依赖死锁与显式 loop 的跨轮次触发也必须区分。

## 4. VM 式模块后端

后端按 AST 模块路径、注册身份、执行身份和 scope 身份定位操作，提供三个视图：

| 视图 | 内容 |
|---|---|
| 静态 IR | 注册、操作组合、值来源、资源关联、原始 impl 绑定 |
| 运行快照 | 当前状态、等待原因、结果摘要、资源状态、实际采用的实现 |
| 事件流 | 开始、等待、完成、失败、取消、获取和释放，以及时间与触发来源 |

同一组视图支持外部工具：

| 功能 | 后端行为 |
|---|---|
| listen | 按模块或执行订阅事件与快照 |
| mock | 为运行场景显式覆盖实现绑定，记录实际选择 |
| stress | 按输入、重复次数和并发度调度独立调用 |
| log/show | 投影模块结构、连接、状态、耗时、等待和资源信息 |

观察不重复执行 impl。mock 保留原始声明；已启动调用固定其有效实现，资源获取与释放必须使用配套实现。stress 仍遵守去重、取消和清理协议。外部触发与 Hanging 一样进入统一调度。

IR 让模块操作边界可见；未经过框架接口或主动上报的宿主函数内部行为，不会自动成为细粒度可观察事件。

## 5. JSON 与插件启动

序列化保存声明：

- Effect IR、AST、Hanging 描述及稳定引用。
- 参数契约、参数准备表达式、配置与版本信息。
- 已绑定实现的稳定标识。

源码 record 直接绑定函数；导出的配置投影把函数绑定表示成实现标识。加载器从已编译插件恢复函数与能力字典，不把函数闭包、类型类字典、活资源或线程直接写入 JSON。

加载流程：

```text
读取配置 → 解码契约与参数 → 解析引用和插件
         → 恢复显式绑定 → 建立运行环境 → 生成计划并启动
```

加载器报告缺失引用、实现或解码错误。这是配置装配所需的解析，不引入逐条 input 连接的额外类型身份证明，也不会动态生成 Haskell instance。

## 6. 完成标准

同一份注册应能从“阅读声明”贯通到“执行一次操作”“按模块观察”“场景替换实现”和“重复负载测试”，并保持身份、值与资源规则一致。具体实现顺序和验证场景见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。
