# Hanging：事件入口与恢复

Hanging 是 AST 主控制树之外的 hook 树或列表，承载 callback、suspend、wait 和监听恢复。它引用 [AST.md](AST.md) 的模块或 [EFFECT.md](EFFECT.md) 的操作，通过 [INTERPRETER.md](INTERPRETER.md) 回到统一调度。

## 挂载内容

| 内容 | 用途 |
|---|---|
| 所属模块与执行身份 | 标识谁挂起、谁等待 |
| 所属 scope | 限定回调有效期和资源使用范围 |
| 事件来源 | 声明由什么事件唤醒 |
| 恢复位置或触发目标 | 声明恢复哪次执行或发起什么新调用 |
| 有效、等待、取消状态 | 防止已失效入口重新驱动业务 |

Hanging 保存控制描述与运行记录的关联；可序列化描述使用注册引用，宿主回调闭包留在运行时。

## 生命周期

1. 执行遇到等待或订阅时建立挂载，记录所属执行和 scope。
2. 事件到达后进入统一调度，解析恢复目标。
3. 恢复原执行或创建新执行，遵守相应身份、参数与资源规则。
4. 完成、取消或 scope 退出时，注销或使挂载失效。

回调不能绕过后端直接复用已经关闭的资源。scope 结束时先协调使用者和监听，再按 [RESOURCE.md](RESOURCE.md) 的关闭协议释放。

动态 hook、事件合并、重复投递和并发恢复是保留的扩展方向；相关策略尚未固定，不能假定每个事件都会安全地立即重入同一 impl。
